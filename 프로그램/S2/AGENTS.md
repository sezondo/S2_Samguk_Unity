## MCP Write Approval

- MCP 도구를 사용해 외부 서비스에 쓰기 작업을 수행하기 전에는 반드시 사용자에게 명시적으로 허락을 받아야 한다.
- 쓰기 작업에는 Notion 페이지 생성/수정/삭제, GitHub 이슈/PR/댓글/라벨/assignee/상태 변경, 데이터베이스/뷰 수정, 기타 외부 서비스 상태를 바꾸는 모든 MCP 호출이 포함된다.
- 읽기 전용 MCP 호출은 허락 없이 사용할 수 있다.
- 사용자가 같은 요청 안에서 특정 쓰기 작업을 명확히 지시한 경우에만 해당 작업을 허락한 것으로 본다.

## 작업 및 답변 규칙

- 답변과 설명은 한국어로 작성한다.
- 사용자가 "작업해봐", "작업해보자"처럼 실제 작업 시작을 명확히 지시하기 전에는 코드/컴포넌트를 수정하지 않고, 어떤 작업을 할지 사용자와 먼저 토론한다.
- 사용자가 직접 명령하거나 부탁하기 전까지는 컴포넌트 수정을 진행하지 않는다.
- 버그가 발생했거나 문제가 의심되는 경우에는 코드와 컴포넌트를 읽고 확인할 수 있지만, 수정은 사용자 지시가 있을 때 진행한다.
- 사용자가 명시적으로 요청하지 않은 대규모 리팩토링은 반드시 사용자 허락을 받은 뒤 진행한다.
- 수정 후에는 어떤 파일을 왜 바꿨는지 짧게 요약한다.
- 코드를 작성할 때 필요한 부분에는 주석을 붙이며, 주석은 한국어로 작성한다.
- 새로 추가하거나 의미가 바뀌는 멤버 변수, 인스펙터 노출 필드, 주요 런타임 상태 변수에는 어떤 값인지 한국어 주석을 붙인다.
- 새로 추가하거나 의미가 바뀌는 함수에는 무엇을 하는 함수인지 한국어 XML 주석을 붙인다.
- 지역 변수는 계산 과정이 복잡하거나 이름만으로 의미가 부족한 경우에만 주석을 붙인다.
- `Debug.Log`, `Debug.LogWarning`, `Debug.LogError`로 출력하는 런타임 로그 문장은 기본적으로 한국어로 작성한다.
- 사용자를 호출하거나 부를 때는 "주인님" 이라고 부른다.

## Context 참조 규칙

- 런타임 컴포넌트 참조는 카테고리별 Context를 통해 모아서 관리한다.
- Player 계열 컴포넌트는 `PlayerContext`에 참조를 추가하고, 다른 Player 컴포넌트는 `PlayerContext`에서 꺼내 사용한다.
- Enemy 계열은 추후 `EnemyContext`, NPC 계열은 추후 `NPCContext`처럼 도메인별 Context를 만든다.
- 기능 컴포넌트가 같은 루트의 다른 핵심 컴포넌트를 직접 `GetComponent<T>()`로 찾지 않는다. 필요한 참조는 해당 Context에 추가한다.
- Context는 참조 주머니 역할만 한다. 튜닝 수치, 상태 변경 정책, 계산 로직을 넣지 않는다.
- Context에서 얻은 참조의 내부 값을 직접 수정하지 않고, 각 컴포넌트가 제공하는 함수나 요청 메서드를 사용한다.
