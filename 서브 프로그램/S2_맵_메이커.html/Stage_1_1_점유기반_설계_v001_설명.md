# 점유 기반 설계 v001

S2_Map_Maker.html에서 같은 이름의 JSON을 불러온다. 기존 1-1수정1 파일과 별개의 15×15 설계 예제다. 셀 크기 1, 유진 배율 0.25를 아트 기준으로 사용한다.

## 설계
- 외곽: 맵 바깥으로 이어지는 건물·담장, 55칸.
- A: ㄴ자 정비소, 16칸.
- B: 길쭉한 창고, 8칸.
- C: 원통형 저장 시설, 21칸.
- D: ㄱ자 주거·상점 건물, 11칸.
- E: 소형 설비실, 2칸.
- 낮은 엄폐 3칸은 진입 불가로 검사했다. 맵 메이커 내부는 낮은 엄폐 위의 표식을 허용하지만 이번 파일의 경로와 배치물은 해당 칸을 사용하지 않는다.
- 시작 (1,0), 해킹 (8,10), 목표 (12,13). 해킹으로 목표 활성화하는 기획이며 문은 없다. 게임의 해킹 동작을 구현하는 파일은 아니다.
- 모든 이동 칸 109개가 연결되고 세 경로 모두 벽·엄폐를 피한다. 적의 시야·전술 난이도는 미검증이다.

## 아트 제작 기준
- 건물 모양과 높이는 아트 담당이 설계한다. 건물별 안내는 기존 칸별 notes에 기록해 다시 저장해도 보존되도록 했다. 새 JSON 필드는 필요하지 않다.
- 바닥 점유와 그림의 외곽은 다르다. 처마/벽 높이는 바닥 영역 밖으로 보일 수 있으나, 이동 칸에 물리적인 몸체를 추가하지 않는다. 뒤편 캐릭터 가림은 별도로 처리한다.
- 원통형은 점유 21칸 안에 들어가는 곡면과 받침을 설계하고, 비워 둔 모서리 칸을 침범하지 않는다. 칸별 정사각형 기둥으로 그리지 않는다.
- 외곽 배경은 보드 밖으로 연장한다. 맵 전체 그림을 생성한 뒤 배치에 끼워 맞추지 않고, 점유 기준의 바닥/건물 초안부터 검토한다.

## 검증
- 실제 HTML의 normalize 함수로 JSON을 불러와 지형·배치·경로·메모가 그대로 유지됨을 코드로 확인했다. 도구 업데이트 없이 기존 v6 형식으로 표현 가능했다.
- Unity 씬과 기존 JSON은 변경하지 않았다. 컴퓨터 플러그인과 Play 테스트는 사용하지 않았다.
