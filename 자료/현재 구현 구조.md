# 현재 구현 구조

이 문서는 Notion에 길게 두지 않는 프로그래밍 구현 구조를 보관한다.

최신 기준: 2026-05-12

## 전체 흐름

- 입력은 `PlayerInput`이 받고, 플레이어 상태 변경은 `PlayerFSMManager`가 담당한다.
- 실제 기능은 `PlayerMovement`, `PlayerMeleeAttack`, `PlayerWeaponThrow`, `PlayerHackController`, `PlayerDodge` 같은 컴포넌트가 나누어 처리한다.
- `PlayerContext`는 플레이어 핵심 참조를 모아 각 기능 컴포넌트가 공유한다.
- `PlayerData`는 이동, 회피, 근접 공격, 무기 투척, 해킹 튜닝값을 가진다.

## 입력

- 이동: `Move`
- 조준: `Look`
- 근접 공격: `MeleeAttack`
- 무기 투척 / 회수 / 해킹 취소: `WeaponThrow`
- 회피: `Dodge`
- 해킹 진행: `Hack` / E
- 일반 상호작용 예약: `Interact` / F
- 기존 화살 선택 입력 `Previous`, `Next`는 폐기했다.

## 플레이어 FSM

현재 주요 상태는 다음 기준으로 사용한다.

- `Idle`: 기본 조작 가능 상태
- `MeleeAttack`: 근접 공격 중
- `WeaponAiming`: 투척 조준 중
- `WeaponThrowing`: 검이 날아가는 중
- `WeaponReceiving`: 검이 돌아오는 중
- `Hacking`: 해킹 대상에 검이 박힌 뒤 해킹 조작 가능한 상태
- `Dodge`: 회피 중
- `Dead`: 사망 상태

해킹 관련 전환 기준은 다음과 같다.

- 검이 해킹 대상에 박힌 사건이 발생하면 `PlayerWeaponThrow`가 이벤트를 발생시킨다.
- `PlayerHackController`는 이 이벤트를 받아 활성 해킹 세션을 등록한다.
- `WeaponReceiving` 상태에서 해킹 대상에 박힌 검이 확인되면 `Hacking` 진입을 시도한다.
- `Hacking` 중에는 이동 가능, 공격 불가, 회피 가능, 사망 가능이다.
- `Hacking -> Dodge -> Hacking` 복귀가 가능하다.
- `Dead` 진입 시 현재는 해킹 세션을 정리한다. 검 처리 정책은 추후 결정한다.

## 검 투척

### PlayerWeaponThrow

- 투척 입력, 회수 입력, 투척 무기 스폰과 회수를 담당한다.
- 해킹 대상에 박힘을 직접 처리하지 않고 `EmbeddedHackWeaponRegistered` 이벤트로 알린다.
- 검 회수 완료는 `WeaponRecovered` 이벤트로 알린다.
- `PlayerHackController`를 직접 명령하지 않도록 이벤트 기반 구조로 분리했다.

### ThrownWeapon

투척 무기의 물리 상태는 다음으로 나뉜다.

- `Outbound`: 날아가는 중
- `Embedded`: 해킹 대상에 박힌 상태
- `Returning`: 플레이어에게 돌아오는 중

충돌 처리 기준은 다음과 같다.

- `Outbound`일 때만 타격과 해킹 대상 감지를 처리한다.
- `IHackable`과 `IDamageable`을 둘 다 가진 대상은 `IHackable`을 우선한다.
- `Embedded` 상태에서는 다른 적이나 오브젝트와 접촉해도 대미지나 추가 상호작용을 하지 않는다.
- 해킹 완료 또는 취소 시 `BeginReturnFromHack()`으로 회수를 시작한다.

## 해킹 / 전자 부적 삽입

개발 중 코드 명칭은 `Hack`을 사용하고, 게임 내 정식 명칭은 추후 `전자 부적 삽입`으로 정리할 예정이다.

### 주요 타입

- `IHackable`: 해킹 가능한 대상 인터페이스
- `HackableData`: 해킹 소요 시간 등 대상별 데이터만 보관하는 `ScriptableObject`
- `PlayerHackController`: 해킹 세션과 타이머를 관리하는 플레이어 컴포넌트
- `HackableTest`: 임시 테스트용 해킹 대상 컴포넌트

### HackProgressState

- `None`: 해킹 대상 없음
- `Ready`: 검이 해킹 대상에 박혀 있고, 플레이어가 아직 E를 누르지 않은 상태
- `Progress`: E 입력 후 해킹 타이머 진행 중
- `Complete`: 해킹 완료
- `Cancel`: 해킹 취소 또는 실패

### 진행 규칙

- `Ready`에서 E 입력 시 `Progress`로 전환한다.
- `Ready` 또는 `Progress`에서 우클릭을 누르면 `Cancel`로 전환하고 검을 회수한다.
- `Progress` 중 플레이어와 검 사이 거리가 `PlayerData.hack.maxHackDistance`를 넘으면 `Cancel`로 전환한다.
- 해킹 완료 시 `Complete` 처리 후 검을 자동 회수한다.
- 회피 중에도 해킹 타이머는 계속 돈다.
- 회피 중 타이머가 완료되면 회피 종료 뒤 `Hacking`으로 돌아왔을 때 완료 처리가 반영된다.

## 도깨비 환도 비주얼

### PlayerWeaponVisualFSM

- 실제 투척 무기 상태와 플레이어 FSM 상태를 바탕으로 비주얼 상태를 결정한다.
- `EmbeddedForHack` 상태를 추가했다.
- `ActiveThrownWeapon.IsEmbeddedForHack`이 참이면 이동, 회피 상태보다 `EmbeddedForHack`을 우선한다.

### PlayerWeaponVisualMotion

- 일반 상태에서는 플레이어 주변 오프셋, 조준, 공격, 회수 모션을 처리한다.
- `EmbeddedForHack` 상태에서는 비주얼 검을 실제 `ThrownWeapon` 위치에 고정한다.
- 이 상태에서는 이동 입력이나 Dodge 연출을 따라가지 않는다.

### PlayerWeaponVisualPresentation

- 비주얼 상태별 렌더러, 그림자, Trail, 이펙트 표현을 담당한다.

## 전투 공통

- `IDamageable`: 피해를 받을 수 있는 대상 인터페이스
- `IHackable`: 해킹 가능한 대상 인터페이스
- `VfxManager`: 공통 VFX 스폰 관리

## 레거시 정리 상태

- 기존 화살 선택 입력은 폐기했다.
- `PlayerArrowSwitcher`는 기존 씬/프리팹 참조 호환을 위해 빈 컴포넌트로 남기고 비활성화한다.
- `PlayerBow`, `Arrow`, `ArrowData`, `ArrowDataTable`은 추후 완전 삭제 여부를 판단한다.
- Notion에는 폐기 구조를 길게 보관하지 않고, 필요한 세부 내용은 이 문서와 작업일지에 남긴다.
- 앞으로 Notion 페이지에 프로그램 구현 내용을 반영할 때는 이 문서의 현재 구현 구조도 함께 업데이트한다.

## 추후 검토 사항

- `PlayerWeaponThrow`와 `PlayerHackController`의 이벤트 경계가 장기적으로 적절한지 검토한다.
- 사망 시 박힌 검을 즉시 소멸시킬지, 회수시킬지, 현장에 남길지 결정한다.
- 해킹 연결선 연출을 추가할 때 거리 단계별 색상 기준을 정한다.
- 게임 내 명칭 `전자 부적 삽입`을 UI/대사/튜토리얼에 어떻게 녹일지 정한다.
