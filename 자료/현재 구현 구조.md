# 현재 구현 구조

이 문서는 Notion에 길게 두지 않는 프로그래밍 구현 구조를 보관한다.

최신 기준: 2026-05-16

## 전체 흐름

- 입력은 `PlayerInput`이 받고, 플레이어 상태 변경은 `PlayerFSMManager`가 담당한다.
- 실제 기능은 `PlayerMovement`, `PlayerMeleeAttack`, `PlayerWeaponThrow`, `PlayerHackController`, `PlayerDodge` 같은 컴포넌트가 나누어 처리한다.
- `PlayerContext`는 플레이어 핵심 참조를 모아 각 기능 컴포넌트가 공유한다.
- `PlayerData`는 이동, 회피, 근접 공격, 무기 투척, 해킹 튜닝값을 가진다.
- 현재 `PlayerData`에는 `Health`, `Movement`, `Weapon Throw`, `Dodge`, `Hack` 기준의 실제 사용 필드만 둔다.

## 데이터 검증 기준

- 플레이어 튜닝값은 `PlayerData`, `MeleeComboData`, `PlayerMeleeAttackData`, `HackableData`, `PlayerWeaponVisualData` 같은 데이터 에셋을 기준으로 사용한다.
- 데이터 에셋이나 필수 하위 데이터가 비어 있으면 인스펙터 fallback 값을 대신 쓰지 않는다.
- 누락 또는 무효 값은 `Debug.LogError`로 드러내고, 해당 컴포넌트를 비활성화하거나 해당 흐름 진입을 중단한다.
- `PlayerMovement`, `PlayerDodge`, `PlayerHealth`, `PlayerWeaponThrow`, `PlayerHackController`, `PlayerMeleeAttack`, `PlayerWeaponVisualFSM`은 시작 시 필요한 데이터 연결과 핵심 수치 범위를 `HasValidData()`에서 검증한다.
- 런타임에 해킹 대상이 들어와야 알 수 있는 `HackableData`는 `PlayerHackController.HasValidHackableData()`에서 별도로 검증한다.
- `PlayerWeaponVisualMotion`, `PlayerWeaponVisualPresentation`의 검 비주얼 튜닝값은 `PlayerWeaponVisualData`에서만 받으며, 컴포넌트 인스펙터 fallback 값은 사용하지 않는다.
- `PlayerWeaponVisualMotion.ApplyData()`와 `PlayerWeaponVisualPresentation.ApplyData()`는 검증하지 않고 적용만 담당한다. 데이터 검증은 `PlayerWeaponVisualFSM.HasValidData()`가 담당한다.

## 입력

- 이동: `Move`
- 조준: `Look`
- 근접 공격: `MeleeAttack`
- 무기 투척 / 회수 / 해킹 취소: `WeaponThrow`
- 회피: `Dodge`
- 해킹 진행: `Hack` / E
- 일반 상호작용 예약: `Interact` / F
- 기존 화살 선택 입력 `Previous`, `Next`는 폐기했다.

## 플레이어 FSM

현재 주요 상태는 다음 기준으로 사용한다.

- `Idle`: 기본 조작 가능 상태
- `MeleeAttack`: 근접 공격 중
- `WeaponAiming`: 투척 조준 중
- `WeaponThrowing`: 검이 날아가는 중
- `WeaponReceiving`: 검이 돌아오는 중
- `Hacking`: 해킹 대상에 검이 박힌 뒤 해킹 조작 가능한 상태
- `Dodge`: 회피 중
- `Dead`: 사망 상태

해킹 관련 전환 기준은 다음과 같다.

- 검이 해킹 대상에 박힌 사건이 발생하면 `PlayerWeaponThrow`가 이벤트를 발생시킨다.
- `PlayerHackController`는 이 이벤트를 받아 활성 해킹 세션을 등록한다.
- `WeaponReceiving` 상태에서 해킹 대상에 박힌 검이 확인되면 `Hacking` 진입을 시도한다.
- `Hacking` 중에는 이동 가능, 공격 불가, 회피 가능, 사망 가능이다.
- `Hacking -> Dodge -> Hacking` 복귀가 가능하다.
- `Dead` 진입 시 현재는 해킹 세션을 정리한다. 검 처리 정책은 추후 결정한다.

## 검 투척

### PlayerWeaponThrow

- 투척 입력, 회수 입력, 투척 무기 스폰과 회수를 담당한다.
- 해킹 대상에 박힘을 직접 처리하지 않고 `EmbeddedHackWeaponRegistered` 이벤트로 알린다.
- 검 회수 완료는 `WeaponRecovered` 이벤트로 알린다.
- `PlayerHackController`를 직접 명령하지 않도록 이벤트 기반 구조로 분리했다.

### ThrownWeapon

투척 무기의 물리 상태는 다음으로 나뉜다.

- `Outbound`: 날아가는 중
- `Embedded`: 해킹 대상에 박힌 상태
- `Returning`: 플레이어에게 돌아오는 중

충돌 처리 기준은 다음과 같다.

- `Outbound`일 때만 타격과 해킹 대상 감지를 처리한다.
- `IHackable`과 `IDamageable`을 둘 다 가진 대상은 `IHackable`을 우선한다.
- `Embedded` 상태에서는 다른 적이나 오브젝트와 접촉해도 대미지나 추가 상호작용을 하지 않는다.
- 해킹 완료 또는 취소 시 `BeginReturnFromHack()`으로 회수를 시작한다.

## 해킹 / 전자 부적 삽입

개발 중 코드 명칭은 `Hack`을 사용하고, 게임 내 정식 명칭은 추후 `전자 부적 삽입`으로 정리할 예정이다.

### 주요 타입

- `IHackable`: 해킹 가능한 대상 인터페이스
- `HackableData`: 해킹 소요 시간 등 대상별 데이터만 보관하는 `ScriptableObject`
- `PlayerHackController`: 해킹 세션과 타이머를 관리하는 플레이어 컴포넌트
- `HackableTest`: 임시 테스트용 해킹 대상 컴포넌트

### HackProgressState

- `None`: 해킹 대상 없음
- `Ready`: 검이 해킹 대상에 박혀 있고, 플레이어가 아직 E를 누르지 않은 상태
- `Progress`: E 입력 후 해킹 타이머 진행 중
- `Complete`: 해킹 완료
- `Cancel`: 해킹 취소 또는 실패

### 진행 규칙

- `Ready`에서 E 입력 시 `Progress`로 전환한다.
- `Ready` 또는 `Progress`에서 우클릭을 누르면 `Cancel`로 전환하고 검을 회수한다.
- `Progress` 중 플레이어와 검 사이 거리가 `PlayerData.hack.maxHackDistance`를 넘으면 `Cancel`로 전환한다.
- 해킹 완료 시 `Complete` 처리 후 검을 자동 회수한다.
- 회피 중에도 해킹 타이머는 계속 돈다.
- 회피 중 타이머가 완료되면 회피 종료 뒤 `Hacking`으로 돌아왔을 때 완료 처리가 반영된다.

## 도깨비 환도 비주얼

### PlayerWeaponVisualFSM

- 실제 투척 무기 상태와 플레이어 FSM 상태를 바탕으로 비주얼 상태를 결정한다.
- `EmbeddedForHack` 상태를 추가했다.
- `ActiveThrownWeapon.IsEmbeddedForHack`이 참이면 이동, 회피 상태보다 `EmbeddedForHack`을 우선한다.

### PlayerWeaponVisualMotion

- 일반 상태에서는 플레이어 주변 오프셋, 조준, 공격, 회수 모션을 처리한다.
- `EmbeddedForHack` 상태에서는 비주얼 검을 실제 `ThrownWeapon` 위치에 고정한다.
- 이 상태에서는 이동 입력이나 Dodge 연출을 따라가지 않는다.

### PlayerWeaponVisualPresentation

- 비주얼 상태별 렌더러, 그림자, Trail, 이펙트 표현을 담당한다.

## 전투 공통

- `IDamageable`: 피해를 받을 수 있는 대상 인터페이스
- `IHackable`: 해킹 가능한 대상 인터페이스
- `VfxManager`: 공통 VFX 스폰 관리

## 말풍선 대사 시스템

1차 대사 시스템은 분기, 선택지, 다국어, 세이브 연동 없이 대사 시퀀스를 말풍선으로 표시하는 전역 시스템이다.

### 데이터

- `DialogueLineData`: 한 줄 대사 데이터다. CSV 전환을 고려해 `speakerTag`, `text`, `advanceByInput`, `advanceByTime`, `autoAdvanceTime`를 가진다.
- `DialogueSequenceData`: 여러 `DialogueLineData`를 순서대로 들고 있는 `ScriptableObject`다.
- `DialogueSequenceData.canPlayerMoveDuringDialogue`는 해당 시퀀스 재생 중 플레이어 이동 가능 여부를 정한다.
- 대사 데이터에는 실제 씬 Transform을 직접 넣지 않고, `speakerTag`만 둔다.

### 실행

- `DialogueManager`: 전역 싱글톤 대사 매니저다. 현재 1차 정책은 한 번에 하나의 `DialoguePlaybackSession`만 허용한다.
- `DialoguePlaybackContext`: `sessionId`, `DialogueSequenceData`, 대사를 시작한 `DialogueEventTrigger`를 담아 전역 이벤트로 전달한다.
- `DialogueEventTrigger`: 바닥, 문, NPC, 이벤트존 같은 이벤트 오브젝트에 붙어 대사를 시작한다.
- `DialogueStartMode.Interact`: 플레이어가 근접한 상태에서 `Interact(F)`를 누르면 대사를 시작한다.
- `DialogueStartMode.Touch`: 플레이어와 접촉하면 대사를 시작한다.
- `DialogueEventTrigger.allowRepeat`는 접촉/상호작용할 때마다 반복 재생할지, 최초 1회만 재생할지 정한다.
- 이미 대사가 재생 중이면 새 재생 요청은 거부한다. 내부는 `DialoguePlaybackSession` 기준으로 둬 추후 동시 재생 확장을 고려한다.

### 말풍선 표시

- `DialogueSpeaker`: 실제 발화자 오브젝트에 붙는다. 자체 `speakerTag`와 자기 `SpeechBubbleView`를 가진다.
- `DialogueEventTrigger`는 해당 대사에서 사용할 `DialogueSpeaker[]` 후보를 인스펙터로 가진다.
- `DialogueManager`는 현재 줄의 `speakerTag`를 후보 `DialogueSpeaker[]` 안에서만 찾는다. 전역 `GameObject.FindGameObjectWithTag`나 Unity Tag는 사용하지 않는다.
- 발화자를 찾지 못하면 오류 로그를 띄우고 해당 대사 세션을 중단한다. fallback 발화자는 두지 않는다.
- `SpeechBubbleView`는 UI 말풍선 표시를 담당한다.
- 말풍선 조각은 `LeftCap`, `LeftScale`, `Center`, `RightScale`, `RightCap` 5개를 기준으로 받는다.
- 왼쪽/센터/오른쪽 원본 조각 크기는 유지하고, 센터 양옆의 `Scale` 조각 width만 대사 길이에 맞춰 늘리거나 줄인다.
- 말풍선 위치는 `speakerAnchor`의 월드 좌표를 화면/UI 좌표로 변환해 따라간다.

### 이동 잠금

- `DialogueManager`는 대사 시작/줄 변경/종료를 전역 이벤트로 발행한다.
- `PlayerMovementLock`은 전역 대사 이벤트를 구독해 `Dialogue` 사유의 이동 잠금을 걸거나 푼다.
- `PlayerMovement`는 기존 FSM 이동 가능 조건과 `PlayerMovementLock.IsLocked`를 함께 확인한다.
- `PlayerFSMManager`는 대사 시스템을 직접 알지 않는다.

## 레거시 정리 상태

- 기존 화살 선택 입력은 폐기했다.
- `PlayerInput`은 이제 `WeaponThrow` 액션만 무기 투척 입력으로 사용하며, 레거시 `Bow` 액션 fallback은 제거했다.
- `PlayerLoadout`에서는 화살 테이블, 보유 화살, 장착 화살 API를 제거하고 플레이어 데이터와 근접 콤보 데이터만 보관한다.
- `PlayerContext`에서는 `PlayerArrowSwitcher` 참조를 제거해 플레이어 런타임 의존성을 끊었다.
- `PlayerArrowSwitcher`는 기존 씬/프리팹 참조 호환을 위해 빈 컴포넌트로 남기고 비활성화한다.
- `PlayerArrowSwitcher`, `PlayerBow`, `Arrow`, `ArrowData`, `ArrowDataTable`은 `Assets/Script/Legacy`에 모아둔 고립된 레거시 코드다.
- 활/화살 레거시는 당장 삭제하지 않고, 씬/프리팹 정리 후 완전 삭제 여부를 판단한다.
- Notion에는 폐기 구조를 길게 보관하지 않고, 필요한 세부 내용은 이 문서와 작업일지에 남긴다.
- 앞으로 Notion 페이지에 프로그램 구현 내용을 반영할 때는 이 문서의 현재 구현 구조도 함께 업데이트한다.

## 문서 기록 기준

- `작업일지.md`는 날짜별 요약식으로 작성한다.
- 각 날짜 기록은 `핵심`, `검증`, `다음` 정도만 남긴다.
- 세부 구현 설명은 길게 작업일지에 쌓지 않고, 최신 구조로 남길 내용만 `현재 구현 구조.md`에 반영한다.
- 폐기된 구조나 오래된 디버깅 과정은 특별한 이유가 없으면 작업일지에 보관하지 않는다.

## 다음 구현 목표

- Unity에서 `DialogueManager` 전역 오브젝트를 씬에 배치한다.
- 실제 발화자 오브젝트에 `DialogueSpeaker`와 `SpeechBubbleView`를 연결한다.
- 이벤트 오브젝트에 `DialogueEventTrigger`, `DialogueSequenceData`, 발화 후보 `DialogueSpeaker[]`를 연결한다.
- 플레이어 오브젝트에 `PlayerMovementLock`을 추가한다.
- 실제 플레이에서 접촉 시작, `F` 시작, 대사 중 이동 잠금, `F` 또는 시간 진행, speakerTag 매칭을 테스트한다.

## 추후 검토 사항

- `PlayerWeaponThrow`와 `PlayerHackController`의 이벤트 경계가 장기적으로 적절한지 검토한다.
- 사망 시 박힌 검을 즉시 소멸시킬지, 회수시킬지, 현장에 남길지 결정한다.
- 해킹 연결선 연출을 추가할 때 거리 단계별 색상 기준을 정한다.
- 게임 내 명칭 `전자 부적 삽입`을 UI/대사/튜토리얼에 어떻게 녹일지 정한다.
