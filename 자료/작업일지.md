# 2026-04-16 작업 기록

이 섹션은 2026-04-16 기준 최신 코드 구조를 설명한다. 2026-04-14 기록 중 `PlayerBow`가 직접 조준 방향을 계산하거나 `PlayerData.bulletPrefab`을 사용한다는 설명은 더 이상 최신 구조가 아니다.

## 오늘 결정한 방향성

- `PlayerBow`가 너무 많은 책임을 가지지 않도록 역할을 줄인다.
- 마우스 위치와 조준 방향 계산은 활 전용이 아니므로 `PlayerAim`이라는 공용 컴포넌트로 분리한다.
- 어떤 화살을 발사할지는 `arrowTypeId`만 넘기는 방식이 아니라, 타입에 맞는 `ArrowData`를 먼저 찾고 그 안의 프리팹을 생성하는 방식으로 간다.
- 화살 외형이나 이펙트가 달라질 수 있으므로, 화살 종류별 프리팹 분리를 전제로 한다.
- 기본 화살 동작은 `Arrow`가 담당하고, 화염/독/번개 화살은 나중에 `Arrow`를 상속해서 확장할 수 있게 둔다.

## 추가된 구조

- `PlayerAim`
- `ArrowData`

## PlayerAim 역할

- 마우스 월드 위치를 기준으로 플레이어에서 마우스까지의 조준 방향을 계산한다.
- 마우스 기준을 사용할 수 없으면 이동 방향을 fallback으로 쓴다.
- 이동 입력도 없으면 마지막 유효 조준 방향을 유지한다.
- `AimDirection`으로 정규화된 조준 방향을 제공한다.
- `AimSide`로 `PlayerSide8` 기준 8방향 조준 값을 제공한다.
- 이 값은 활뿐 아니라 근접 공격 방향, 캐릭터 방향, 애니메이션 방향에도 재사용할 수 있다.

## ArrowData 역할

- 화살 종류별 데이터 ScriptableObject다.
- `arrowTypeId`: 화살 종류 번호
- `arrowPrefab`: 이 타입으로 생성할 실제 화살 프리팹
- `projectileSpeed`: 이 타입의 기본 발사 속도
- 일반/화염/독/번개 화살처럼 외형이나 충돌 구성이 다를 경우, `ArrowData`별로 다른 프리팹을 넣는다.

## PlayerData 변경

- 기존 `bulletPrefab` 직접 참조 방식은 제거했다.
- `equippedArrowTypeId`는 현재 장착된 화살 종류 번호를 의미한다.
- `arrowDataList`는 사용할 수 있는 화살 데이터 목록이다.
- `GetEquippedArrowData()`는 `arrowDataList`에서 `equippedArrowTypeId`와 같은 `arrowTypeId`를 가진 `ArrowData`를 찾아 반환한다.

## PlayerBow 최신 역할

- `PlayerInput`에서 우클릭 입력을 읽어 `BowCharge` / `BowShoot` 상태 요청을 보낸다.
- `PlayerAim.AimDirection`을 받아 최종 발사 방향을 계산한다.
- 차지 시간에 따라 spread를 계산해 명중 오차를 적용한다.
- `PlayerAim.AimSide`를 받아 8방향 firePoint 중 하나를 고른다.
- `PlayerData.GetEquippedArrowData()`로 현재 장착 화살 데이터를 찾는다.
- `ArrowData.arrowPrefab`을 생성하고, `Arrow.Initialize(direction, speed, typeId)`로 초기값만 넘긴다.
- 실제 화살 이동, 수명, 충돌 처리는 `Arrow`가 담당한다.

# 2026-04-24 작업 기록

오늘은 플레이어 HP, 피격 무적, 공통 데미지 인터페이스 구조를 추가하고 관련 설계 결정을 정리했다.

## 오늘 변경한 핵심

- `PlayerHealth`를 추가했다.
- `PlayerHealth`는 HP, 피격 후 무적 시간, 사망 시 `Dead` 전이 요청을 담당한다.
- `IDamageable` 인터페이스를 추가했다.
- `PlayerHealth`와 `EnemyHealthTest`가 `IDamageable`을 구현하도록 바꿨다.
- `Arrow`와 `MeleeHitbox`가 `EnemyHealthTest`를 직접 찾지 않고 `IDamageable`을 찾아 데미지를 주도록 정리했다.
- `PlayerData`에 `invincibleDuration`을 추가했다.
- 피격 무적 시간은 `PlayerData.invincibleDuration`을 우선 사용하고, 데이터가 없거나 값이 0 이하이면 `PlayerHealth`의 fallback 값을 사용한다.

## PlayerHealth 역할

- `PlayerData.maxHp`를 기준으로 최대 HP를 정한다.
- `TakeDamage(int damage)`로 데미지를 받는다.
- 데미지를 받은 뒤 HP가 남아 있으면 `PlayerHitJudgment.Invincible`로 들어가 추가 데미지를 막는다.
- 무적 시간이 끝나면 `PlayerHitJudgment.Vulnerable`로 돌아간다.
- HP가 0 이하가 되면 `PlayerFSMManager.ForceDead()`를 호출해 `Dead` 상태로 들어간다.
- `OnHealthChanged`, `OnHitJudgmentChanged`, `OnDied` 이벤트는 유지한다.

## 데미지 가능 조건

- `Dead` 상태에서는 데미지를 받지 않는다.
- `Dodge` 상태에서는 데미지를 받지 않는다.
- `PlayerHitJudgment.Invincible` 상태에서는 데미지를 받지 않는다.
- 위 조건이 모두 아니면 데미지를 받을 수 있다.

## 설계 결정

- `PlayerDataContainer`는 아직 만들지 않는다.
- 이유는 `ArrowData`, `MeleeAttackData`, 장비/무기 데이터가 섞이기 시작하면 단순 데이터 컨테이너의 책임이 애매해질 수 있기 때문이다.
- 현재는 각 스크립트가 필요한 데이터만 직접 참조하는 구조를 유지한다.
- `invincibleDuration`은 플레이어 밸런스 값으로 보고 `PlayerData`에 둔다.
- `ignoreDamageDuringDodge` 같은 선택 옵션은 제거하고, Dodge 무적은 FSM 규칙으로 고정한다.
- `OnDied`는 유지한다. HP가 0이 된 순간의 이벤트로 사용하고, 실제 행동 상태 기준은 `PlayerFSMManager`의 `Dead` 상태를 본다.
- `ResetHealth()`에서 Dead 상태 복구는 아직 하지 않는다. 부활/리스폰이 필요해질 때 별도 루트로 설계한다.

## 이름 정리

- `PlayerHitJudgment` 값 이름을 `NonHit / Hit`에서 `Vulnerable / Invincible`로 바꿨다.
- 실제 용도가 피격 모션 여부가 아니라 데미지 수신 가능 여부이기 때문이다.

## EquippedArrow 구조 정리

- `ArrowDataTable.allArrowData`는 게임 안에 존재하는 모든 화살 데이터 목록이다.
- `PlayerLoadout.ownedArrowTypeIds`는 현재 플레이어가 가진 화살 ID 목록이다.
- `PlayerLoadout.equippedArrowIndex`는 `ownedArrowTypeIds` 배열 안에서 현재 몇 번째 화살을 장착 중인지 나타낸다.
- `PlayerLoadout.EquippedArrow`는 `ownedArrowTypeIds[equippedArrowIndex]` 값을 꺼낸 뒤, `ArrowDataTable.FindByTypeId()`로 실제 `ArrowData`를 찾아 반환한다.
- 예를 들어 `ownedArrowTypeIds = [0, 2]`, `equippedArrowIndex = 1`이면 현재 장착 화살 ID는 2이고, `ArrowDataTable`에서 `arrowTypeId == 2`인 화살 데이터를 찾아 발사한다.

## 화살 교체 테스트 중 확인한 점

- Q/E 입력 로그가 뜨는데 계속 `Equipped arrow type: 0`만 출력되는 상황이 있었다.
- 원인은 `PlayerLoadout.ownedArrowTypeIds`에 `[0]` 하나만 들어 있었기 때문이다.
- `ArrowDataTable`에 `arrowTypeId` 0, 1 화살이 모두 있어도, `ownedArrowTypeIds`에 1이 없으면 플레이어가 1번 화살을 가진 것으로 보지 않는다.
- 따라서 테스트에서 0번과 1번 화살을 교체하려면 `ownedArrowTypeIds`를 `[0, 1]`로 설정해야 한다.
- `ownedArrowTypeIds = []`이면 장착 화살을 찾을 수 없어 발사가 실패할 수 있다.
- `ownedArrowTypeIds = [0]`이면 기본 화살 0번만 가진 상태이므로 기본 화살은 정상 발사되지만 Q/E 교체는 0번만 반복된다.

# 2026-05-12 작업 기록

오늘은 해킹 시스템의 책임 방향과 Embedded 검 비주얼 고정 문제를 정리했다.

## 해킹 이벤트 구조 변경

- `PlayerWeaponThrow`가 `PlayerHackController`를 직접 참조해 해킹 진입과 세션 정리를 호출하던 구조를 제거했다.
- `PlayerWeaponThrow`는 이제 `EmbeddedHackWeaponRegistered`, `WeaponRecovered` 이벤트만 발행한다.
- `PlayerHackController`가 위 이벤트를 구독해 해킹 세션 등록과 회수 후 세션 정리를 처리한다.
- `PlayerHackController`는 `WeaponReceiving` 상태 진입 이벤트 또는 검 박힘 이벤트를 기준으로 `TryEnterHackingForEmbeddedWeapon()`을 내부에서 호출한다.
- 이 변경으로 `PlayerWeaponThrow`는 검 투척/회수 사실만 알리고, 해킹 상태 판단은 `PlayerHackController`가 담당하도록 책임 방향을 정리했다.

## EmbeddedForHack 비주얼 고정 수정

- `PlayerWeaponVisualFSM`에서 투척체가 `EmbeddedForHack` 상태이면 플레이어 FSM 상태보다 먼저 `EmbeddedForHack` 비주얼 상태를 반환하도록 수정했다.
- 이 변경으로 해킹 중 플레이어가 이동하거나 `Dodge` 상태가 되어도 검 비주얼이 `Orbit`으로 떨어져 플레이어를 따라가지 않는다.
- `PlayerWeaponVisualMotion`에서 `EmbeddedForHack` 상태는 SmoothDamp 보간을 사용하지 않고, `ActiveThrownWeapon` 위치에 즉시 고정되도록 수정했다.

## 원인

- 기존에는 `Hacking` 상태에서는 `EmbeddedForHack`로 보였지만, `Dodge` 중에는 `PlayerWeaponVisualFSM.ResolveVisualState()`가 기본 `Orbit`으로 떨어졌다.
- 그 결과 해킹 대상에 박힌 검 비주얼이 플레이어의 이동/회피 기준 Orbit 위치를 따라가는 문제가 있었다.
